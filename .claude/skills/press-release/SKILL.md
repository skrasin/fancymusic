# Пресс-релиз FANCYMUSIC

Полные правила тона, структуры и вёрстки — в `CLAUDE.md` в корне репозитория.
Прочитать его перед работой. Здесь — порядок действий.

Порядок шагов не переставлять: документ в Google Docs собирается последним,
потому что обложку в него подтягивает сам Google по публичной ссылке —
страница должна быть уже опубликована.

## 1. Разобрать материалы

Определить `slug` (латиница, kebab-case: `artist-release-name`), создать
`projects/{slug}/raw-materials/` и сложить туда присланное как есть.

Заполнить `raw-materials/meta.yml` по образцу `templates/meta.yml` — это рабочая
опись: что получено и чего не хватает. Каждый факт только из материалов.
Чего нет — `[УТОЧНИТЬ]`, цитаты нет — `[ЦИТАТА]`. Ничего не додумывать:
ни жанр, ни дату, ни состав участников.

Источником для сборки `meta.yml` не является: страница и документы собираются
из `output/press-release.md` и `page.json`.

## 2. Задать один вопрос

Если в `meta.yml` остались `[УТОЧНИТЬ]` — спросить про самый критичный из них,
одним вопросом, а не списком. Критичность по убыванию: повод для инфоповода →
дата выхода → ссылка на предпрослушивание → обложка → цитата.

Отдельно, один раз в начале работы над релизом: нужны ли посты для соцсетей
или только пресс-релиз.

Блок «О лейбле» брать из `brand/BRAND.md` дословно. Он согласован:
не переписывать, не сокращать и не спрашивать о нём.

## 3. Написать тексты

- `projects/{slug}/output/press-release.md` — на основе
  `templates/press-release.md`. Это единственный источник текста: из него
  собираются и страница, и DOCX, и PDF, и версия для Google Docs.
  Заголовок первого уровня — тот, что должен стоять на странице; строку
  формата и жанра не писать. Разделы «Ссылки» и «Контакты для прессы»
  не писать — сборщики добавят их из `page.json`. Комментарии `<!-- -->`
  допустимы, в вывод не попадают
- `projects/{slug}/output/social.md` — на основе `templates/social.md`,
  если соцсети нужны

Один финальный вариант, без «вот три версии на выбор».

## 4. Сверстать страницу

Скопировать `templates/page.json` в `projects/{slug}/page.json` и заполнить.
Обложку положить рядом со страницей, в `docs/releases/{slug}/`, а имя файла
указать в `values.COVER_FILE` и `values.COVER_URL`. Внешнюю ссылку на чужой
домен не оставлять: поменяется путь — обложка молча отвалится, и в документы
её вложить будет нельзя.

```
python3 tools/build-release-page.py {slug}
```

Сборщик подставит данные в `templates/release-page.html`, встроит спрайт
пиктограмм, размеры файлов и сделает из обложки иконку вкладки
(`favicon-32.png` и `apple-touch-icon.png`). `docs/releases/{slug}/index.html`
руками не править — он перезаписывается.

Раскладка «разворот»: слева белая панель с обложкой, плеером и кнопками
«Ссылки на стриминги» и «Страница релиза», справа скроллится текст.
Ссылки артиста — в блоке «Об артисте», ссылки лейбла — в блоке «О лейбле».

- в `PLAYER_EMBED` оставить ровно один вариант — встроенный плеер площадки
  или `<audio>` с локальным превью
- пиктограммы ссылок: `i-web`, `i-tg`, `i-vk`, `i-ig`, `i-fb`, `i-yt`,
  `i-bc`, `i-sp`, `i-mail`, `i-external`; порядок в `page.json` = порядок
  на странице
- `HEADLINE` не задаётся: заголовок берётся из Markdown

Стили в шаблоне не править: раскладка меняется в `brand/release.css`,
цвета и типографика — в `brand/design-tokens.css`, после правки — 
`./tools/sync-brand.sh`.

Добавить строку релиза в список на `docs/index.html`.

## 5. Собрать DOCX и PDF

```
python3 tools/build-press-docs.py {slug}
```

Проза из `press-release.md`, фактура из `page.json` — те же файлы, что кормят
страницу, поэтому разойтись они не могут. Копии кладутся рядом со страницей,
размеры на кнопках проставляет сборщик страницы, так что после этого шага
страницу пересобрать ещё раз.

Порядок в документах повторяет страницу: обложка рядом с названием, под ними
ссылки на стриминги и на страницу релиза, дальше текст, справки, списки
ссылок, контакты. Строка «FANCYMUSIC · Пресс-релиз · дата» — в самом низу.

В DOCX и PDF обложка вкладывается **только из локального файла**
(`values.COVER_FILE`): туда нужны сами байты картинки. Без файла сборщик
предупредит и оставит пустое место.

## 6. Опубликовать

Закоммитить и запушить в `main`. Дождаться, пока GitHub Pages выложит
страницу: обложка должна открываться по адресу
`https://skrasin.github.io/fancymusic/releases/{slug}/cover.jpg` — без этого
следующий шаг соберёт документ без картинки.

## 7. Сделать версию в Google Docs

Сборщик из шага 5 уже положил `output/press-release.gdoc.html` — простую
разметку, которая переживает конвертацию Google. Обложка в ней дана публичной
ссылкой на копию с GitHub Pages: локальный файл конвертер не видит, а картинку
по http скачивает сам и вкладывает внутрь документа.

Загрузить содержимое файла через `create_file` с `contentMimeType: text/html`,
записать ссылку вида `https://docs.google.com/document/d/{id}/edit?usp=sharing`
в `values.GDOC_URL`, пересобрать страницу и запушить. На странице появится
третья кнопка рядом с DOCX и PDF; без `GDOC_URL` её просто нет.

Два ограничения, о которых надо сказать пользователю:

- **Документ создаётся закрытым.** Доступный инструмент шаринга делится только
  с конкретным адресом, режима «всем, у кого есть ссылка» в нём нет. Открыть
  доступ должен человек: «Настройки доступа» → «Все, у кого есть ссылка» →
  «Читатель». Иначе кнопка на публичной странице приведёт журналиста
  на запрос доступа.
- **Содержимое существующего документа изменить нельзя** — `update_file` меняет
  только название и папку. При правке текста создаётся новый документ, ссылка
  на странице обновляется, доступ на нём надо открыть заново, а старый удаляет
  владелец. Поэтому текст лучше править до рассылки ссылки.

## 8. Проверить и отчитаться

- незакрытых `{{ПЛЕЙСХОЛДЕРОВ}}` не осталось
- все `[УТОЧНИТЬ]` либо закрыты, либо перечислены пользователю списком
- страница открывается, обложка и плеер на месте, на 390px нет
  горизонтальной прокрутки, консоль чистая
- DOCX и PDF отдаются с кодом 200, ссылки в них кликабельные
- сказать пользователю ссылку `https://skrasin.github.io/fancymusic/releases/{slug}/`,
  что осталось уточнить и что нужно сделать руками (доступ к Google Docs)

Домены `fancymusic.ru`, `*.bandcamp.com`, `band.link` и `github.io` закрыты
сетевой политикой рабочего окружения: обложку с сайта лейбла и работу плеера
проверить нельзя, это делает пользователь.
